ADMIN PLANE (port 8081)
-----------------------
{{- if .Values.service.admin.enabled }}
  The admin plane is EXPOSED via Service {{ include "busbar.serviceName" (dict "root" . "suffix" "-admin") }} (bound 0.0.0.0:8081).
  {{- if .Values.adminTLS.enabled }}
  It requires mTLS. Present a client cert chaining to your client CA and an
  admin token (x-admin-token / Bearer) to reach /api/v1/admin/*.
  {{- end }}

  Port-forward the admin Service to a local port:
    kubectl -n {{ .Release.Namespace }} port-forward svc/{{ include "busbar.serviceName" (dict "root" . "suffix" "-admin") }} 8081:{{ .Values.service.admin.port }}
  HTTPS health checks require a client certificate and key even though /healthz
  does not require an admin token. Use your server CA bundle and a hostname in
  the server certificate (for cert-manager, the Service DNS name):
    curl --cacert server-ca.crt --cert client.crt --key client.key \
      --resolve {{ include "busbar.serviceName" (dict "root" . "suffix" "-admin") }}:8081:127.0.0.1 \
      https://{{ include "busbar.serviceName" (dict "root" . "suffix" "-admin") }}:8081/healthz
{{- else }}
  The admin plane is NOT exposed. It stays on loopback (127.0.0.1:8081) inside
  the pod.

  Forward the pod's admin port to your workstation (the image has no curl):
    kubectl -n {{ .Release.Namespace }} port-forward {{ if .Values.governance.enabled }}statefulset/{{ include "busbar.statefulSetName" . }}{{ else }}deployment/{{ include "busbar.fullname" . }}{{ end }} 8081:8081
{{- if .Values.adminTLS.enabled }}
  Use HTTPS with the server CA and any required client certificate and key.
{{- else }}
    curl http://127.0.0.1:8081/healthz
{{- end }}

  To EXPOSE the admin plane cluster-wide, set service.admin.enabled=true. Because
  busbar refuses to boot with a non-loopback admin listener that lacks mTLS, you
  must ALSO enable mTLS:
    --set adminTLS.enabled=true
{{- end }}

CONFIG MUTABILITY
-----------------
{{- $userCfgSection := (get (.Values.config | default dict) "config") | default dict }}
{{- if not (kindIs "map" $userCfgSection) }}{{- $userCfgSection = dict }}{{- end }}
{{- /* Same defaults configmap.yaml applies. */}}
{{- $mut := .Values.configMutability | default dict }}
{{- $mode := $mut.mode | default "locked" }}
{{- if .Values.existingConfigMap }}
  existingConfigMap is set, so the chart renders no config and configMutability
  is not applied: config.locked / config.overlay come from ConfigMap
  {{ .Values.existingConfigMap }}.
{{- else if hasKey $userCfgSection "locked" }}
  config.locked: {{ $userCfgSection.locked | toJson }} (set in .Values.config.config, which overrides
  configMutability.mode = {{ $mode }}).
{{- else }}
  configMutability.mode = {{ $mode }}
{{- if eq $mode "locked" }}
  config.locked: true -> the admin API REFUSES config mutations. Change config by
  editing values and running `helm upgrade` (reloadOnConfigChange rolls the pods).
{{- else if eq $mode "overlay" }}
  {{- $overlayFile := $mut.overlayFile | default "/tmp/busbar-overlay.json" }}
  {{- if hasKey $userCfgSection "overlay" }}
  {{- /* The chart adds no overlay when the user set one, so report only the user's file. */}}
  {{- $overlay := get $userCfgSection "overlay" }}
  {{- $overlayFile = "" }}
  {{- if and (kindIs "map" $overlay) (get $overlay "file") }}{{- $overlayFile = get $overlay "file" }}{{- end }}
  {{- end }}
  {{- if $overlayFile }}
  config.locked: false, overlay at {{ $overlayFile }}.
  {{- else }}
  config.locked: false, and .Values.config.config.overlay sets no overlay file.
  {{- end }}
  Admin-API config mutations persist to the overlay file. If it is on the chart's /tmp
  emptyDir it is POD-LOCAL and EPHEMERAL: mutations are lost on restart and on
  helm upgrade, and multiple replicas will DIVERGE.
{{- else }}
  The chart writes no config.locked/config.overlay: you own them in .Values.config.
{{- end }}
{{- end }}
